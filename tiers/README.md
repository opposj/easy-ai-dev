# Tiered Dockerfile (build-arg variant)

Same structure as the root `Dockerfile` (prep_brew → brewed → final, one-line style) with a single build argument selecting the tier. The root `Dockerfile` is untouched.

```sh
docker build --build-arg TIER=lite -t ai-dev:lite .
docker build --build-arg TIER=default -t ai-dev:default .
docker build -t ai-dev:full -t ai-dev .    # ARG TIER defaults to full
```

| `TIER` | For | Contents |
| --- | --- | --- |
| `lite` | AI agents, `docker run --rm`, no TUI | brew core (curl, git, glibc, gcc) + zsh, jq, ripgrep, fd, gh, uv, bun (+node symlink), unzip, sevenzip, file-formula |
| `default` | TUI lovers, `-it` | lite + vim, less, zellij, hunk, bat, eza, starship, lazygit, fastfetch, fzf, zoxide, yazi, tlrc, bash-completion@2, wl-clipboard, forgecode, hyperfine, man-db, texinfo, universal-ctags, gdb, go, rustup, duckdb, ffmpeg-full, imagemagick-full, poppler, resvg + oh-my-zsh + dotfiles |
| `full` | everything | default + ruby, perl, php, lua, luarocks, elixir, zig, swift, r, clojure, sbcl + quicklisp + alire |

## Tier selection mechanism

- `ARG TIER=full` (stage-scoped in `brewed` and the final stage) gates the brew formula list and the oh-my-zsh/quicklisp setup via shell `if`s.
- The final stage bakes the tier into the image: `ENV BUILD_TIER=$TIER`.
- `.zshrc` starts with `[[ $BUILD_TIER == lite ]] && return` — in `lite` every TUI-oriented setting (oh-my-zsh, starship, fzf, zoxide, forge, plugins) is skipped, leaving a plain zsh. The guard is inert when `BUILD_TIER` is unset, so the original root `Dockerfile` image behaves exactly as before.
- All tiers use zsh: the entrypoint is a small shim that loads the brew
  environment (`brew shellenv`) and then execs the requested command or falls
  back to interactive zsh, and `.zshenv` sets up the remaining paths
  (glibc/ruby-gems/rustup/bun) inside zsh. This is why zsh is in the lite
  formula list.

## Usage

```sh
docker run -it --rm --privileged ai-dev:lite        # interactive zsh, minimal config
docker run --rm ai-dev:lite uv --version            # one-off commands, brew env included
docker run -it --rm --privileged ai-dev:default     # full TUI experience
docker run -it --rm --privileged ai-dev:full        # everything
```

The entrypoint is a small shim generated by the build:

```sh
#!/bin/sh
eval "$(/home/linuxbrew/.linuxbrew/bin/brew shellenv)"   # brew env for dispatched commands
if [ $# -gt 0 ]; then exec "$@"; fi                       # bare `docker run ... <cmd>`
exec /home/linuxbrew/.linuxbrew/bin/zsh                   # otherwise interactive zsh
```

The `eval` is what makes `docker run --rm ai-dev:lite uv --version` work without `-c`:
commands launched this way never run `.zshenv`, so PATH/HOMEBREW_* come from the
wrapper. Interactive zsh still sources `.zshenv`, which skips its own `brew shellenv`
because `HOMEBREW_PREFIX` is already set.

Verify per-tier contents/sizes with brew-leaf-size:

```sh
docker run --rm -v "$PWD/brew-leaf-size:/tools/brew-leaf-size" ai-dev:lite python3 /tools/brew-leaf-size/brew-leaf-size.py
```
